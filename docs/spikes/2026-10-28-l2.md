# L2: bundle and loader, locally

Run on 2026-10-28 with Astro 7.4.2, Rolldown 1.2.15 (through Vite), Rollup 4.65.1, `systemjs@6.15.1` and Deno 2.9.5. Sources are in [`2026-10-28-l2/`](2026-10-28-l2/). The app has three on-demand routes: `/`, `/env` (an `astro:env` secret and `Astro.clientAddress`) and `/code` (Astro's `<Code>`, so Shiki). A minimal adapter in `app/astro.config.mjs` builds it with `vite.ssr.noExternal: true`, so every dependency is bundled.

## 1. Files reachable per route

Rolldown splits the server build at Astro's own `import()` boundaries: 324 files, 12 MB, each Shiki language and theme its own chunk. `analyze.mjs` runs Rollup with `format: 'system'` over that output, and `driver.js` renders each route once under `s.js` in a fresh Deno process, counting the parts it fetches.

| Rollup output | Files | Total | Eager (entry closure) | Largest part |
| --- | --- | --- | --- | --- |
| Default chunking | 320 | 11.6 MB | 2 files, 671 kB | 818 kB (a grammar) |
| `experimentalMinChunkSize: 32 kB` | 314 | 11.6 MB | 2 files, 674 kB | 818 kB |

Parts fetched after the eager part, per route, measured by rendering:

| Route | Default chunking | Merging below 32 kB |
| --- | --- | --- |
| `/` | 3 files, 3 kB | 1 file, 1 kB |
| `/env` | 3 files, 8 kB | 1 file, 6 kB |
| `/code` | 6 files, 1,131 kB | 4 files, 1,129 kB (page, WebAssembly engine, theme, one grammar) |

- One module would be 11.6 MB, over bunny.net's limit. Split, `/code` needs the eager 674 kB plus about 1.1 MB.
- Rollup's option for merging small chunks is `output.experimentalMinChunkSize`. It merged only six chunks here, because most small chunks are separate `import()` targets, but it removed the per-route shared chunks that cost a fetch each.
- `/code` fetches in two rounds: the page first, then the engine, theme and grammar it imports.
- `/env` answered 500 because the driver passes no client address. Expected, not checked further; it is not a loader failure.

Proposed budget for ADR 0007: merge below 32 kB, and at most 8 part fetches for any route, against bunny.net's 50 subrequests per request. The eager part ships inside the script, so it costs no fetch on bunny.net.

## 2. `require(`, `.wasm` and builtins

- No `require(` and no `createRequire` in the server output.
- No `.wasm` imports. Shiki's engine inlines its WebAssembly as base64 (622 kB) and compiles it at runtime. Whether bunny.net allows `WebAssembly` compilation is not checked: add it to S1.
- No `node:` imports at all in this app. A real site will add some, so the builtin check of M2 still applies.

## 3. Retry and concurrent imports

`retry.js` makes the first fetch of a part fail with 503, then imports it again.

- `s.js` caches the failure. The second import fails without a new fetch, so one transient error breaks that part for the life of the isolate.
- `s.js` has no `System.delete`. The full `system.js` (12,325 bytes minified, against 7,976) has it. With `system.js`, deleting the failed entry and importing again fetched once more and succeeded.
- Two concurrent imports of the same part caused one fetch, with both loaders.
- Open for M3: a failure deep in a chain also fails its importers, so recovery has to clear every failed entry, not only the one that failed.

## 4. SHA-256

Measured on bunny.net in S1.1: about 15 ms for 10 MB. Not repeated locally.

## 5. The Action's `_headers` and `_redirects` parser

`site/probe.mjs` runs bunny-edge-deploy's `readSiteConfig`, `analyzeSiteConfig` and `siteRules` (read-only, from its `feat/middleware-deploy` branch) on Cloudflare-style files in `site/`.

- Several headers for one path become one edge rule with extra actions. `Cache-Control` becomes a browser cache rule with only its `max-age`.
- A `200` rewrite is refused with a clear error.
- `! X-Frame-Options` (detaching a header) is dropped without a warning.
- Placeholders are not translated. `/blog/* /posts/:splat` redirects to the literal `/posts/:splat`, and `/docs/:slug` only matches the literal text `:slug`.
- A query condition (`/search?q=:q`) is taken as literal path text.
- So the Action supports plain paths and splat matching for headers, and plain paths for redirects. ADR 0008's Cloudflare semantics need the script for the rest, or the Action has to learn them in its own track.

## 6. `_headers` and `_redirects` in the bunny CLI

- The 0.21.0 npm README never mentions either file.
- The 0.21.0 darwin-arm64 binary (65 MB) and the local 0.19.0 binary contain neither file name outside Node's own HTTP internals.
- So the CLI does not read them; whether a `bunny sites` server-side router does is not shown by this search.
