# S1 pack tune: which packing of the server script is fastest on bunny.net

Run on 2026-10-28 against throwaway standalone scripts, all deleted afterwards. The question: of the packing refinements found locally (cheaper unpacking, brotli, a smaller eager part), which make a cold request fastest on bunny.net? The app is the L2 app of the earlier spikes (a small Astro 7 server app with one Shiki `<Code>` block, 314 `System.register` parts). Runtime on bunny.net: Deno 2.7.12, V8 14.7.173.20.

Every number below is **measured** unless it is labeled derived (arithmetic on measured numbers) or expected (not measured). The scripts are in [`2026-10-28-s1-pack-tune/`](2026-10-28-s1-pack-tune/).

## Setup

- `build.mjs` writes every variant from the same parts, with SystemJS 6.15.1 `s.js` as the loader in all of them (S1 packed used `system.js`). Nothing is fetched. Each script answers JSON timings for `?route=<path>`, the HTML with `&html=1`, runtime checks for `?check=1`, and a plain 404 otherwise.
- Variants:
  1. **one**: the entry, the eager part and `/code`'s four parts as functions, nothing else. `/code` only.
  2. **packed**: S1 packed. Every lazy part gzip 9 + base64 in string literals, `atob` + `Uint8Array.from`, `DecompressionStream`.
  3. **fb64**: as 2 with `Uint8Array.fromBase64`, and Shiki's base64 wasm literal taken out of its part and packed as gzipped bytes (exp-unpack's best-rwz).
  4. **brotli**: as 3 with brotli 11.
  5. **manifest**: as 4 with the `entryModules` entries that point at server files removed (tier 1 item 3).
  6. **minify**: as 5 with every part minified by oxc, function and class names kept (tier 1 item 2).
  - **mingz**: as 6 with gzip 9 instead of brotli, added to separate the compression from the rest. `/code` only.
  - **comment**: as 5 with the packed data in a function body comment read with `toString()` (tier 1 item 1). It fails on bunny.net (see Checks), so it is not in the timing tables, and 5 and 6 keep string literals.
- `run.sh` runs rounds over all twelve cells in turn, one Globalping measurement per cell per round from New York, Frankfurt and Singapore, each with a fresh query string. Twelve rounds in two windows, 21:23 to 21:27 and 21:31 to 21:35 UTC. `summarize.mjs` keeps probes served by their own region's PoP (NY; DE or BE; SG) and the isolate's first request (cold).
- Cold means the isolate's first request. "Gap" is time to first byte minus the handler's run time: connection, isolate start and script evaluation. "Run" is the handler: the eager import, then the render, which includes unpacking.
- HTML check: the handler hashes the body (SHA-256, with server island `e=` values and UUIDs masked, of which this app has none).

## Checks (`?check=1`)

Measured on 18 fresh isolates (3 per script, all from Frankfurt, every one the isolate's first request):

| Check | Result |
| --- | --- |
| `typeof Uint8Array.fromBase64` | `function` |
| `DecompressionStream('gzip')` and `('brotli')` | both decompressed the test string |
| `import('node:zlib')` | resolves, `brotliDecompressSync` is a function |
| ICU in a fresh isolate | first `localeCompare` 0 to 0.4 ms, first `Intl.DateTimeFormat` 0.1 to 0.8 ms, locale `en-US` (locally 4.1 and 2.1 ms) |
| `toString()` of a function with a body comment | **the comment is gone**: `function packedSource() {}` |

- bunny.net reprints the script before it evaluates it. The code stored through the API still holds the comment (2,729,281 characters), but at runtime every comment form is dropped: plain `/* */`, `/*!`, `/** @preserve`, `/** @license`, and `//` (measured with `probe.js`). A function written as `function tight(a,b){return a+b}` comes back as `function tight(a, b) {\n  return a + b;\n}`.
- So the comment variant answers 500 on every route: the loader reads an empty comment.
- ICU is already set up when the script runs, or costs too little to measure. Expected from this: exp-eager's tier 2 `Intl` item and the `localeCompare` route sort item save nothing on bunny.net.

### Derived

- **`fromBase64` plus the wasm rewrite is the big step.** `/code` unpacking went from 59 / 79 / 83 to 13 / 21 / 19 ms, and the handler from 211 / 307 / 303 to 113 / 178 / 162 ms. The wasm part went from 30 to 42 ms to 3 to 5 ms.
- **One module pays Shiki's own wasm decode.** `one`'s handler (161 / 246 / 229 ms) is 48 to 68 ms slower than fb64's, although nothing in it is unpacked: Shiki's `Uint8Array.from(atob(...))` over 622 kB runs inside its render. So at the `/code` median, variants 5, 6 and mingz beat one module in all three regions (by 20 to 103 ms) and fb64 by 17 to 45 ms, while brotli was 38 ms slower in New York and faster elsewhere.
- **Brotli costs 2 to 6 ms of unpacking per `/code` request and saves 0.45 MB of script.** minify against mingz: 1 to 3 ms more unpacking in total and 4 to 13 ms lower time to first byte, with a gap 7 to 13 ms lower. That fits S1's 17 to 22 ms of startup per MB of script (expected about 8 to 10 ms for 0.45 MB), but the difference is inside the spread of the samples.
- **Manifest stripping and minify** moved `/` time to first byte from 129 / 210 / 149 (brotli) to 104 / 181 / 154 ms, and `/code` from 287 / 328 / 318 to 195 / 311 / 275 ms. Each step is smaller than the p90 spread, so their separate effects are not resolved here. The direction is the same in five of six region cells.
- **The eager import does not scale like S1's unpacking did.** 13 to 22 ms here against 11 ms locally (1.2 to 2 times), where exp-eager expected 4 to 7 times. Together with the 0.0 ms calls of function parts, this suggests bunny.net compiles functions ahead (a code cache, for example) while strings passed to `eval` are compiled on use. That is a guess; it was not checked.

## What it decides

- **Use variant 6: brotli 11, `Uint8Array.fromBase64`, Shiki's wasm packed as bytes, `entryModules` stripped of server files, oxc minify with names kept, packed data in string literals.** It had the lowest `/code` median in New York and Singapore and was within 6 ms of the lowest in Frankfurt (manifest, 305 against 311), the smallest script, and the lowest `/` medians in two of three regions. It is faster than one module on `/code` in all three regions.
- **gzip is an acceptable fallback** (mingz within 4 to 13 ms of variant 6). No fallback is needed for bunny.net itself: `fromBase64`, `DecompressionStream('brotli')` and `node:zlib` all exist there.
- **Drop the comment storage.** bunny.net reprints scripts and drops every comment, so data in a comment does not reach the runtime. The build cannot rely on any comment surviving, `//# sourceURL` and license comments included.
- **Drop the ICU work for bunny.net.** ICU is set up before the script runs, so the lazy `Intl` transform and the route sort item gain nothing there. They may still matter on other hosts.
- **Apply the Shiki wasm rewrite whenever Shiki's `wasm-inlined` part is present**, packed or not: it is the largest single saving measured here.

## Not covered

- One module with Shiki's decode rewritten (exp-unpack's `one-wasm-fast`). Expected to close most of the gap between `one` and the packed variants; not measured on bunny.net.
- `node:zlib` `brotliDecompressSync` or `gunzipSync` in place of `DecompressionStream`: available, not timed.
- Whether bunny.net reprints the script on every isolate start or once per deploy, and what that costs. The gap includes it either way.
- More than 8 to 12 cold samples per cell. Frankfurt gaps are bimodal in several cells (p90 up to 300 ms), so differences under about 20 ms are not resolved.
- Other routes and apps, the server island endpoint, POST requests, and memory.
- exp-eager's tier 2 (no patches to Astro's dist were built).
