# S1 minify: does minifying the packed server script make a cold request faster on bunny.net

Run on 2026-10-28 against throwaway standalone scripts, all deleted afterwards. The question: S1 pack tune's variant 5 (no minify) and variant 6 (minified) differed by up to 34 ms on `/code` medians with 9 to 12 samples per cell, inside the p90 spread. Is minifying a measurable gain, and does Rolldown's own minifier do as well as oxc-minify? Same app as S1 pack tune (the L2 app: Astro 7, one Shiki `<Code>` block, 314 `System.register` parts).

Every number below is **measured** unless it is labeled derived (arithmetic on measured numbers) or expected (not measured). The scripts are in [`2026-10-28-s1-minify/`](2026-10-28-s1-minify/).

## Setup

- `build.mjs` is S1 pack tune's builder cut down to three variants. All three: SystemJS 6.15.1 `s.min.js` as the loader, brotli 11, `Uint8Array.fromBase64`, Shiki's wasm packed as bytes, `entryModules` stripped of server files, packed data in string literals. Each answers JSON timings for `?route=<path>`, the HTML with `&html=1`, and a plain 404 otherwise.
  - **v5**: no minify (pack tune variant 5).
  - **v6r**: every part minified with Rolldown's `minify` from `rolldown/utils` (rolldown 1.2.15, already in the repo through Vite), function and class names kept, `codegen.legalComments: 'inline'`.
  - **v6o**: every part minified with the `oxc-minify` package 0.156.0, installed outside the repo, with pack tune's options (names kept, legal comments dropped, the default).
- **Pack tune's variant 6 was not built with oxc-minify.** Its builder imports `minify` from `rolldown/utils`; no `oxc-minify` package is installed in the repo. So v6r with pack tune's options is pack tune variant 6, and v6o is the standalone package that was assumed.
- `run.sh` runs 32 rounds over six cells (three variants by `/code` and `/`), one Globalping measurement per cell per round from New York, Frankfurt and Singapore, each with a fresh query string, so drift hits every variant in each round. Rounds ran from 21:52 to 22:37 UTC, with a 34 minute pause midway at the Globalping hourly limit.
- `summarize.mjs` keeps probes served by their own region's PoP (NY; DE or BE; SG) and the isolate's first request (cold). Per region it reports median / p90, the difference of medians with a 95% bootstrap interval (10,000 resamples), and a two-sided Mann-Whitney U p value. It also pools the three regions by subtracting each region's median before comparing.
- "Gap" is time to first byte minus the handler's run time: connection, isolate start and script evaluation. "Run" is the handler: eager import, then render including unpacking.

## Minifier output

Measured locally over all 314 parts with the same options (names kept, legal comments dropped):

- Rolldown's binding embeds `oxc_minifier` 0.155.0; the package is 0.156.0.
- **313 of 314 parts are byte-identical.** The one difference is 2 bytes in the eager server island manifest part (`!a.test(x)&&b` against `a.test(x)||b`).
- One part holds a legal comment (`@license`, in the eager part). Keeping it inline adds 1,204 bytes.
- The packed tables of v6r and v6o are byte-identical. The two scripts differ only in the eager part, by 1,206 bytes.

## Statistical answer

- **On `/`, minifying is a small real gain: about 8 to 11 ms of cold time to first byte, nearly all of it in the startup gap.** Both minified variants beat v5 when pooled (p 0.002 and 0.010), the direction holds in all six region cells, and the run time moves by 3 ms or less. Derived: that fits S1's 17 to 22 ms of startup per MB of script for the 0.42 MB minify removes (expected 7 to 9 ms).
- **On `/code`, the gain is not resolved.** v6r pooled -14 ms (p 0.012), v6o pooled -2 ms (p 0.48), with the two scripts byte-identical except for 1.2 kB in the eager part. Derived: the 12 ms between them is noise, so the noise floor on `/code` at this sample size is about that large, and a gain of 5 to 10 ms (the `/` result) cannot be told apart from it there.
- With twelve per-region tests, about one p below 0.05 is expected by chance. Only v6r on `/` in Singapore stays below 0.05 after a Bonferroni correction (0.05 / 12).
- **Rolldown's minifier matches oxc-minify.** It is the same minifier (`oxc_minifier` 0.155.0 against 0.156.0) and gave identical output on 313 of 314 parts. Every difference measured between v6r and v6o on bunny.net is inside the noise described above.
- **Pack tune's 34 ms was mostly noise.** At 25 to 31 samples per cell, the same comparison came out at -18 and -12 ms (Frankfurt, Singapore) and swung by 88 ms in New York between two nearly identical scripts.

## What it decides

- **Keep minifying, with Rolldown's `minify` from `rolldown/utils`, function and class names kept.** It costs no new dependency, saves 0.42 MB of script and about 10 ms of cold start on bunny.net (measured on `/`), and does not change the HTML. The gain is small; it is a reason to keep minify on by default, not a reason to build anything else around it.
- **Do not add `oxc-minify` as a dependency.** Rolldown ships the same minifier.
- **Keep legal comments with `codegen.legalComments: 'inline'` if the build wants them in the packed parts.** It cost 1.2 kB here, and comments inside packed string data survive (only comments in the script's own source are dropped by bunny.net, see S1 pack tune). Whether they should be kept is a licensing question this spike does not answer.

## Not covered

- Minifying the eager part and the packed parts separately. Expected from the gap result: most of the gain comes from the eager part and the script's parse, not from the packed parts, which are only decompressed and evaluated on use. Not measured.
- `mangle` or `compress` settings beyond names kept, and names not kept (smaller, but breaks code that reads `.name`).
- Why New York is bimodal (two hosts behind the NY PoP, or two probe networks, for example). Globalping probe identity was not recorded.
- Warm requests: 57 warm samples were excluded and not analyzed.
- Other apps, other routes, memory, and build time of the minify step.
